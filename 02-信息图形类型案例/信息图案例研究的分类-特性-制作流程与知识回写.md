# 信息图形案例研究三阶段判定与知识回写流程（核心规范）

> 目的：把 02 文件夹从“风格标签清单”转变为**以真实案例为证据的表现特性、视觉编码、视觉叙事、制作方法与可复建流程**知识库。2026-11-24 补充《信息图形设计导论》研读与论述框架。

## 核心原则：先01，再02，再视觉设计

**顺序不可颠倒：**
1. **先判断01：五种基本数据逻辑中是哪一类**；观察信息的主导关系，判定唯一主分类。
2. **再判断02：它属于哪些信息图形表现形式标签**；为存储选定一个主标签，必要时记录辅助标签，不能用外观反推01逻辑。
3. **最后分析并提炼：视觉编码、视觉叙事、风格特征、制作方法和制作流程**；这些是每个案例提供的具体研究成果，须有图像／数据证据。
4. **完成后双向知识回写**：01更新“数据逻辑的普遍规律与案例链接”；02更新“该表现形式的设计特性、方法、流程及案例证据”。`04-统计图形分析` 可以作为统计方法的交叉参考，不改变01或02的归属。

> 核查对象顺序是分类→标签→设计。准备阶段可先核实图片与数据来源，以便判断；不意味着分析时要先写制作风格再选择分类。

## 课件研读：从读者问题到论述结论

来源为冯白帆《信息图形设计导论》，下列页码按 PDF 文件页序。第 21、26 页讨论读图与信息架构，第 31–44 页讨论设计任务、编码和读者负担，第 48–68 页展示分类与常用形式，第 86–89 页讨论受众、阅读测试和设计流程，第 91–102、109–117 页讨论形式取舍、证据与信息分层。以下问题和模板为结合本库整理的分析方法。

### 先把主题写成读者能回答的问题

用一句话写清**谁在读、要找什么答案、答案在哪里**。在图上标出标题或图例入口，辨认主任务与辅助任务。同一张图可以承担多项任务，选择最接近核心问题的一项作为论证起点。

| 读者任务 | 先问什么 | 图面上核对什么 |
|---|---|---|
| 展示 | 某对象在某时间的数值是多少？ | 对象、数值、单位能否在同一处配对 |
| 比较 | 谁更多？差多少？ | 比较的时间、单位、分母、基准和刻度是否一致，是否需要读者自己排序或换算 |
| 组织 | 我要找的条目属于哪一组？ | 分类、排序和跳转入口能否快速定位条目 |
| 关联 | 哪些对象、时间或指标相连？ | 连接表示什么，数据支持怎样的关系，结论是否超出证据 |

### 正文沿证据推进

1. **提出问题，给出初步判断。** 先说明图要解决的阅读任务，再按本库 01、02 判定主数据逻辑与表现标签。动态或交互作品可额外记录暂停、筛选等读图条件。
2. **交代数据和口径。** 解释一行记录什么、哪一列用于分类或排序、单位和分母来自哪里。拆表时保持一列一个字段，例如把地区、年份、变化量、单位分列。把图上能直接读到的内容、复算所得、研究者解释和待核实项分开写。
3. **解释图形如何服务任务。** 选有意义的具体标记，按「图上元素 → 对应数据或语义 → 读者如何使用 → 可能误读什么」写。标题、颜色、位置和长度可能分别承担不同任务。比较图先核对同尺和同口径，关系图先核对连接语义，涉及因果时另核实研究证据。尝试提出一种可行的替代编码，写清它减少了哪些操作，又会弱化哪类信息。
4. **描述阅读路径，验证效果。** 信息架构写清「总览 → 分组或证据层 → 细节、图例及来源」的层次。视觉叙事说明读者实际怎样从入口找到证据，并记录可跳读位置。可用一两道读图题记录答案、用时和误读。课件的五秒题可作快速比较的参考，复杂任务可按目标读者所需时间设置。未做读者测试时，把读图效果写成据图判断。
5. **给出可复用结论。** 句式可用「在〔读者任务和数据条件〕下，〔具体画法〕让人能通过〔图面证据〕完成〔阅读动作〕，适用范围是〔条件或限制〕」。复建可依采集与清洗、搭结构、编码与排版、关联呈现的顺序记录，将推演和已知作者工序分开。

### 示范：西班牙各地区失业率变化图

课件第 39–41 页先让读者从地图里找变化较大的地区，再展示条形排序设计。查某地在哪里时，地图位置和地区标签直接支持空间定位。找谁变化更大时，读者在地图中要逐个搜寻、记住并比较地区标值。第 41 页把排序后的条形与小地图并置，条形提供比较入口，小地图保留地理参照。复建时可拆成「地区、起始时期、结束时期、失业率变化值、单位」等字段，先核实变化的口径，再决定排序和数轴。若图面只提供两个时点的差值，结论写这段时间内的变化量，关于逐期变化速度的结论还需要更多时点的数据。

### 评价取舍

课件的评估轮盘提醒分析者按读者和任务讨论抽象程度、信息密度、维度、通用性及简洁程度。写评价时指出具体元素解决了什么阅读问题。可用反问检验装饰和重复标记的作用，例如移去一条参考线后，读者还能否比较数值、辨别方向或找到注释。保留支撑判断的标记与必要细节。

## 第一阶段：01 五大基本数据逻辑主分类（必做）

先脱离颜色、插画、版式和图标风格，问：**信息最核心的关系是什么？** 以数据表字段和对象间关系来判断，不根据“看起来像什么”来判断。

| 01主类型 | 决定性信息关系 | 典型数据结构 | 不能仅凭此判定 |
|---|---|---|---|
| 编年型 Chronological | 时间先后、阶段／过程顺序 | event_id、order_key、start/end、edge | 仅出现箭头或曲线 |
| 层级型 Hierarchical | 上下位、包含、父子或层级关系 | node_id、parent_id、level | 标题字号有大小 |
| 编目型 Cataloged | 同主题的类别、条目、属性与检索关系 | category_id、item_id、attribute | 在一页堆放很多图标 |
| 字母表型 Alphabet | A–Z／拼音／规范字母键排序与检索 | term、alphabet_key、sort_key、language | 使用A/B/C作为装饰编号 |
| 地理图型 Geographical | 地理空间坐标、区域、邻接或位置关系 | place_id、geometry、crs、region_id | 中央是物品结构图或地球装饰 |

**执行判断：**
- 找出最小信息对象：一行数据究竟记录一个事件、节点、类别条目、词条，还是地理实体？
- 找出主要关系键：时间、parent_id、category_id、sort_key、geometry。
- 找出主传播问题和读者必须理解的关系。若移去这个关系，作品主要论点是否丧失？
- 记录支持该类型的图面证据以及为什么其他类型不是主分类。
- 原图信息不足以判断时暂标 `primary_logic: 待分类`，列缺失证据，不为了遵守五选一而凭空断言；核实后再定稿。

**01的研究结果**是基础数据关系及其边界，不能把 HOW-TO、单一图表、3D、ISOTYPE 等当作基础逻辑类型。

## 第二阶段：02 市场表现标签和案例存储位置

在已判断01主逻辑的前提下，识别这张作品**如何呈现信息**，选一个最有解释力的主表现形式作为实际存储目录；一个案例可以有多个辅助表现标签。

现有17种市场表现形式（代码与目录以仓库实际结构为准）：
01 Mixed Charts；02 Informational / List；03 Timeline；04 How-to；05 Process；06 Comparison；07 Location；08 Photo-graphic；09 Hierarchical 表现；10 Single chart；11 Visualized Text；12 Anatomical；13 Visual Resume；14 Sketch style；15 Chronological-Cataloged Hybrid；16 3D；17 Word Cloud。

[03 ISOTYPE信息图](../03-ISOTYPE信息图/00-方法说明.md)收录可选的跨类型**设计方法**标签；只有图符语义、编码单位、标准化和信息转译规则有证据时才标记。出现普通 icon 不等于 ISOTYPE。

**存储规则：** `02/主表现形式/01-案例图/CASE-ID-作品名.png` 对应 `02/主表现形式/02-案例分析/CASE-ID-作品名分析报告.md`。基础数据集和数据字典可放在配套分析的同ID子目录。其它表现标签只建立交叉索引，不重复图片或独立 CASE。

## 第三阶段：由逐图分析提炼特性、编码、叙事与制作方法

**02的核心不是给案例贴标签，而是研究该案例的具体设计特性、方法与流程。** 完整报告应分别回答：

### A. 数据结构（承接01，而不重新按外观归类）
- 数据最小记录粒度和Excel几行几列？字段、主键、关联键是什么？
- 五大主关系是什么？是否存在辅助关系？有没有可获取的原始数据？
- 观察、转录、计算和推断要标注不同证据状态。

### B. 统计图形与计算（如有）
- 用了哪些统计图、统计方法、比例计算或排序聚合？轴线和单位是什么？
- 图标矩阵、剖面示意、流程线等可能不承担统计编码，必须明确区分。
- 视觉修饰不得破坏数值、比例或地理对象一致性。

### C. 视觉编码（将设计从感觉转化为可执行规则）
逐项做 **“视觉变量→图上具体元素→编码的数据／语义→方法→误读风险”** 对照：
- **点**：节点、事件、地理标记、统计样本？
- **线**：连接、时间序列、趋势、引出标注、反馈还是装饰？
- **面／体**：比例、区域、结构分层，还是版面与透视？
- **符号／ISO图标／ISOTYPE**：对象识别、统计单元，还是视觉隐喻？
- **颜色**：类别、顺序、数值强弱、风险还是装饰？
- **位置、大小、形状、文字**：传达何种关系，是否存在刻度、图例、读数与辨认误差？
从具体案例中总结“为什么这样设计有效”“什么条件下会误导”。

### D. 信息框架
拆解总标题、视觉锚点、主要模块、子模块、数据证据、注释和来源的组织结构。标明读者能否跳转查阅、需要按顺序阅读，还是同时支持两种模式。

### E. 视觉叙事
从**入口→问题→证据→比较或转折→观点→行动／结论**恢复作品所引导的阅读顺序；若原作品是非线性目录，则明确其多个入口，不强加虚构故事。分辨叙事箭头与数据因果。

### F. 风格特性与制作方法
在完成A–E后，提炼而不是臆想作者工艺：
- **表现特性**：视觉中心、图文比例、版式秩序、色彩对比、信息密度、符号语言、阅读节奏。
- **可复用方法**：例如“地图定位与比例圆数值分离，通过引出线重新对应”；每条方法注明适用数据条件及限制。
- **制作流程**（由研究者重建）：采集／核实数据 → 清洗与原子化 → 聚合或计算 → 选择统计图与结构图 → 选择符号和视觉变量 → 构建信息层级 → 组织叙事路径 → 精度／可读性／版权审查。
- 不知道作者实际使用的软件、技术、先后步骤时，标注“研究者重建流程”，不能冒称作者真实制作过程。

### G. 提炼成果及证据级别
至少输出“本案例的3–5条特性、2–4条可复用制作方法、若干限制、可重建的数据表与关键制作步骤”。数量是写作建议，不需要强凑。凡只从一幅作品得到的观察，标记**单例发现**；后续跨多个案例复核后才提升为共性规律。

## 第四阶段：回写信息可视化风格仓库

| 写回位置 | 该写什么 | 不该写什么 |
|---|---|---|
| **01-信息图形数据逻辑/对应概念定义.md** | 主关系的定义修订、数据字段和统计边界、经案例支持的组织原则、文字案例链接、修订日期 | 案例图片、单幅作品纯装饰偏好、未经验证的视觉风格当成基本逻辑 |
| **02-信息图形类型案例/该主标签/00-类型说明.md** | 由案例归纳的风格特性、视觉编码规则、信息与叙事框架、制作方法、适用边界、关联CASE列表 | 无数据支持的空泛风格评价、把市场标签当第六基础类型 |
| **02-该标签/02-案例分析/CASE-ID报告.md** | 原图证据、五维详细拆解、数据表与来源、视觉变量映射、复建流程及评价 | 不注明来源的统计数字、未经授权图像复制 |
| **02-案例索引.md** | 唯一CASE-ID、01主分类、02主／辅助标签、原图权利、数据和报告链接 | 同图多次计为多个独立作品 |
| **04-统计图形分析/** | 必要时记录独立统计方法、数据计算和图形通道的交叉研究 | 以统计图替代信息组织分类 |

### 回写动作
1. 先完成案例报告并核对图片来源和许可；
2. 把每条结论映射为【数据逻辑】或【表现／编码／叙事／制作】；
3. 01只写前者的可推广知识与案例文本链接；02写后者，附同CASE引用；
4. 更新类型说明里的“已验证／单例／待验证／反例”状态及修订记录；
5. 在案例索引记录归属和交叉链接；校验相对路径和权利说明。

## 合格标准
新增案例研究必须提供：01归属及排除理由、02主标签及辅助标签、A–E五维、风格特性、制作方法与重建流程、可复用原则及证据边界、图像／数据来源及版权状态、01与02写回位置、案例索引与修订记录。

**重要**：此规范意味着“每次处理新案例时同步更新相关总文档”，并不代表服务器会自动监控 GitHub 或无人值守改写文件。
